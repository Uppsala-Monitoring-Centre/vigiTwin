# Migration notes: blank-tolerant cells, and a clearer arbitration workbook

**Audience:** the secure-side deployment (`llm_dup_pv_secure`) and any tooling
that reads SCLE reviewer submissions, arbitration workbooks, or consensus
records. This document describes the contract changes only; no secure-side code
is modified from this repository.

Two related changes ship together. The first relaxes when a reviewer must fill a
cell; the second makes both workbooks say which cells those are. They share one
cause: an empty cell meant two different things and looked identical either way.

## Summary

The three yes/no misclassification dimensions — `never_event`,
`unexpected_method_behaviour`, `incorrect_or_imprecise_input_data` — no longer
have to be filled in. A blank cell on a misclassified pair now reads as **"no"**,
the same convention the tick-only `S:` / `F:` columns have used since
[migration_notes_scle_form_simplification.md](migration_notes_scle_form_simplification.md).

`error_source_description` is **unchanged**: it is free text with no sensible
blank default, so it remains required on every misclassified pair. The same goes
for `method_difference_explanation` on every disagreement pair.

Nothing in the aggregate performance analysis (Step 1) is affected. The changes
are confined to Steps 2–3 (workbook generation and read-back).

## Why

The previous rule was internally consistent but not discoverable. In the
workbook, a blank-tolerant tick column and a mandatory yes/no cell rendered
identically — an empty white cell with a dropdown — so reviewers generalised
"blank means no" across the boundary and submitted workbooks that failed
read-back. The 2026-08-01 dry run hit exactly this on two pairs.

## Contract changes

| | Before | After |
|---|---|---|
| Blank `never_event` etc. on a misclassified pair | read-back error | resolved to `"no"` |
| Blank `error_source_description` on a misclassified pair | read-back error | read-back error (unchanged) |
| Blank yes/no on a **correctly classified** pair | `None` | `None` (unchanged) |
| `SCLECaseAssessment` all-or-nothing group | the four misclassification fields | the three yes/no fields only |

New module constants in `scle/form.py`, both exported:
`MISCLASSIFICATION_YESNO_DIMENSIONS` and
`MISCLASSIFICATION_REQUIRED_DIMENSIONS`. `MISCLASSIFICATION_DIMENSIONS` remains
their union and still drives `applicable_dimensions`, so which cells are
pre-filled `N/A` has not moved.

The default is applied at read-back, where the auto-context says whether the
question was asked. A pair that is not misclassified carries the `N/A` sentinel
and still reads back as `None`, so a reviewer who edits a cell they should not
have is still caught.

### Read-back invariant

`SCLECaseAssessment.misclassification_answered` still tests
`never_event is not None`. Because read-back resolves blanks, an assessment read
from a workbook has the block set exactly when the pair is misclassified. An
assessment **constructed directly in code** that leaves the yes/no fields `None`
on a misclassified pair breaks that invariant, and its stage and domain ticks
will compare as "not asked" rather than as "nothing ticked". Any secure-side
code that builds `SCLECaseAssessment` objects without going through
`read_reviewer_submission` should set all three fields explicitly.

## Effect on agreement statistics

**No denominator changes.** The three dimensions were previously mandatory on
misclassified pairs, so they were `None` — and therefore skipped by
`compute_agreement` — only on correctly classified pairs, which is still the
case. What changes is that a blank-versus-`yes` pairing, which previously
blocked read-back altogether, now scores as a genuine disagreement.

## Workbook changes for reviewers

- Response cells that **must** be filled are shaded pale yellow (`FDF0D5`):
  the always-applicable questions, plus `error_source_description` on
  misclassified pairs and `method_difference_explanation` on disagreement pairs.
  Unshaded response cells may be left blank, and blank there is an answer of
  "no".
- The instructions sheet gained a shading legend (item 2), and the per-question
  guidance comments state which cells are blank-tolerant.

Cell fills are cosmetic — read-back does not inspect them — so a workbook
generated by 0.8.0 still reads back correctly under 0.9.0. Reissuing is
worthwhile only so reviewers see the shading.

## Arbitration workbook changes

The arbitration sheet gained the same fill vocabulary and four layout changes.

### Column order

```
Pair ID | Reference label | Adjudicator output | [Confusion cell] | [Joint stratum]
Free-text (A) | Free-text (B)
{dim} (A) | {dim} (B) | {dim} consensus     ... per structured dimension
Method-difference (A) | Method-difference (B) | Consensus method-difference
Free-text materially different | Consensus free-text | Arbiter rationale
```

`Free-text (A)` / `Free-text (B)` **moved** from the end to before the first
dimension, so the arbiter reads both assessments before judging any single
answer. They are not duplicated: read-back indexes columns by header, and a
repeated header would silently keep only the last one.

### Pre-filled consensus for agreed dimensions

The workbook holds only structurally-disagreeing *pairs*, but within a row most
dimensions usually agree. Those consensus cells were blank, so the arbiter could
not see which cells actually needed a decision. They are now pre-filled with the
agreed value and shaded as do-not-edit context; only genuinely disagreeing cells
are blank, shaded pale yellow, and carry a dropdown.

**`merge_consensus` now raises** if an arbitration workbook supplies a consensus
value for a dimension the reviewers agreed on and it differs from the agreed
value. Previously such an edit was silently discarded — the `va == vb` branch
never consulted the arbitration. Provenance is unchanged: agreed dimensions stay
`reviewer_agreement`. Clear the cell or restore the pre-filled value to proceed.

### `N/A` for dimensions that never applied

A dimension outside a pair's applicable set now writes the `N/A` sentinel into
its `(A)`, `(B)` **and** consensus cells instead of leaving three blanks that
read as unanswered questions. Applicability is taken from the auto-context via
`applicable_dimensions`, not from either reviewer's answer, which cannot tell
"not asked" from "nothing ticked". `implicated_feature_domains` still renders an
applicable-but-empty answer as `""` — an empty list is a real answer.

Read-back treats the sentinel as empty, so it never enters
`consensus_dimensions`.

### Method-difference explanation carried into arbitration

`method_difference_explanation` is free text and so is not a structured
dimension; it never reached the arbiter. Three columns now carry it:
`Method-difference (A)`, `Method-difference (B)`, and one
`Consensus method-difference`. There is deliberately **no** second
materially-different flag and **no** second rationale — `Arbiter rationale`
covers both free-text blocks, and `Free-text materially different` continues to
refer to the free-text assessment alone.

Pair selection is unchanged: rows are still chosen by structural disagreement
only, so differing method-difference texts do not pull a pair into arbitration.

### Model and table changes

- `ArbitrationDecision.consensus_method_difference: str = ""` (new, defaulted).
- `ConsensusAssessment.consensus_method_difference: str = ""` (new, defaulted).
- `scle_consensus_*.csv` gains a `consensus_method_difference` column, between
  `free_text_materially_different` and `arbiter_rationale`.

Both new fields default to `""`, so an existing serialized record still
validates.

## What the secure side needs to do

1. Upgrade the installed `llm-dup-dev` to 0.9.0.
2. Regenerate and reissue any reviewer workbook not yet completed, so reviewers
   get the shading and the corrected guidance. Already-completed workbooks do
   not need regenerating.
3. Re-run the arbitration build. Workbooks that failed only on blank yes/no
   cells now pass; a blank `error_source_description` on a misclassified pair
   still fails, and those cells must be filled by the reviewer.
4. Answers already collected need no migration. A workbook completed under the
   old rules has all three yes/no cells filled explicitly, which reads back
   identically under the new rules.
5. Reissue any arbitration workbook not yet completed. An arbitration workbook
   written by 0.8.0 still **reads back** correctly — read-back matches columns by
   header, so the reordering is harmless and the missing method-difference column
   simply comes back empty — but an arbiter working the old sheet gets none of
   the pre-filling, none of the `N/A` marking, and no way to record a consensus
   method-difference. Reissue for the arbiter's benefit, not to avoid an error.
6. Expect the consensus CSV to gain one column; update any downstream reader
   that pins the column count.
